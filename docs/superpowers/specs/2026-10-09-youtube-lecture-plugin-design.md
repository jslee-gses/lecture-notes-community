# 한국어 유튜브 강의 노트 플러그인 설계

작성일: 2026-10-09

## 목적과 성공 기준

사용자는 Codex에서 YouTube 강의 URL 하나를 입력해 한국어 자막을 정제하고, 2단계 목차·강의 전체 요약노트·용어집을 얻는다. 결과는 `lecture.json` 한 파일로 로컬에 보존하고 Railway 웹 서버에 전송한다. 서버가 돌려준 공유 URL을 아는 사람은 강의 내용과 원본 영상의 해당 시점을 함께 탐색할 수 있다.

첫 버전은 한국어 강의 최대 3시간을 대상으로 한다. 사용할 수 있는 한국어 자막이 없으면 이유를 알리고 중단한다. 음성 자동 전사, 영상 다운로드·편집·저장, 웹에서 URL을 입력해 처리를 시작하는 기능은 범위에 넣지 않는다. 기존에 설치된 `lecture-pipeline` 플러그인은 구조와 검증 아이디어를 참고하되 코드는 새로 작성한다.

완료 기준은 다음과 같다.

- Codex 플러그인 명령 한 번으로 유효한 한국어 강의를 처리하고 공유 URL을 받는다.
- 2단계 목차, 전반 요약노트, 용어집, 정제 전사의 항목은 실제 자막 구간과 시간 정보에 연결된다.
- 자막 부재, 잘못된 URL, 생성물 검증 실패, 업로드 실패가 어느 단계에서 발생했는지 알 수 있다. 업로드 실패 때는 같은 `lecture.json`으로 업로드만 재시도할 수 있다.
- 공유 URL을 아는 사람은 로그인 없이 결과를 열 수 있고, 공개 강의 목록이나 순차적인 ID로 다른 결과를 찾을 수 없다.

## 시스템 경계

### Codex 플러그인과 로컬 처리기

새 플러그인 이름은 `lecture-notes`로 한다. Codex 명령 `$lecture-notes <youtube-url>`이 스킬의 진입점이다. 플러그인은 `SKILL.md`의 판단 절차와 Python 스크립트의 결정적 처리 절차로 구성한다. Python은 URL 검증, 자막 수집, 전처리, 청크 구성, JSON 조립·검증·업로드를 맡는다. Codex 모델은 기술 용어 오인식 교정, 목차 구성, 요약노트와 용어집 작성 등 의미 판단을 맡는다. 별도 LLM API 키는 요구하지 않는다.

`yt-dlp`로 영상 파일 없이 한국어 자막과 제목·길이·영상 ID를 로컬에서 확보한다. 한국어 자동 생성 자막을 처리 대상으로 삼고, 해당 자막을 확보하지 못하면 명확한 오류로 종료한다. 자막 수집은 서버가 아니라 Codex 실행 기기에서 수행한다. 클라우드 IP에서의 비공식 자막 접근 차단 가능성을 피하기 위한 배치이며, 로컬에서도 YouTube 접근은 실패할 수 있으므로 오류를 그대로 보고한다.

로컬 작업 디렉터리에는 원본 자막, 정규화한 시간별 문장, 판단 단계별 중간 JSON, 최종 `lecture.json`을 남긴다. 자막 정제는 기술 용어 오인식, 구두점, 문장 경계를 보수적으로 고친다. 발화의 주장이나 예시를 삭제하거나 새로 쓰지 않는다. 3시간 강의를 여러 청크로 나누되 청크 경계에는 읽기 전용 문맥을 제공하고, 전역 문장 번호를 유지한다. 실패한 청크나 단계만 다시 실행할 수 있다.

### Railway 서버와 웹

Railway에 Python 웹/API 서비스 하나와 PostgreSQL 서비스 하나를 배포한다. 웹/API는 FastAPI와 서버 렌더링 HTML, 작은 JavaScript 모듈로 구현한다. 한 서비스가 JSON 업로드 API, 공유 페이지, 정적 리소스를 제공한다. PostgreSQL에는 강의 메타데이터, `lecture.json` 본문(JSONB), 업로드 실행 ID, 공유 토큰을 저장한다. 영상 파일은 저장하지 않는다.

업로드 요청은 HTTPS와 `Authorization: Bearer <LECTURE_UPLOAD_TOKEN>`으로 보호한다. 토큰은 서버 환경변수와 로컬 실행 환경에만 두며 JSON과 로그에 쓰지 않는다. 업로드마다 로컬에서 생성한 `run_id`를 보내고 서버는 이를 고유값으로 취급한다. 같은 파일의 재시도는 같은 공유 URL을 돌려주고, 새 처리 실행은 새 결과로 저장한다. 공유 URL은 암호학적 난수 토큰을 사용한다. 페이지는 검색 엔진 색인을 요청하지 않으며 공개 목록 API를 제공하지 않는다. 링크를 가진 사람은 내용을 볼 수 있으므로 사용자가 URL을 전달할 때 그 범위를 결정한다.

## 데이터 흐름과 계약

1. URL에서 영상 ID를 검증하고 한국어 자막과 메타데이터를 확보한다.
2. 시간 정보가 있는 문장으로 정규화하고 청크별로 용어 오인식을 교정한다.
3. 전체 문장 범위를 빠짐없이 덮는 메인·세부 목차를 만든다. 각 목차 항목에 제목, 간단한 요약, 시작·끝 문장과 시간을 둔다.
4. 전반 요약노트를 짧은 개요와 핵심 내용 항목으로 만든다. 각 항목은 설명과 근거 문장·시점을 가진다.
5. 강의에서 실제로 설명하거나 사용하는 용어를 추려 쉬운 해설과 첫 설명 위치를 기록한다.
6. 최종 JSON을 스키마와 교차 참조 규칙으로 검증해 로컬에 저장한 뒤 서버로 업로드한다.
7. 서버가 같은 계약으로 검증하고 저장한 후 공유 URL을 반환한다.

`lecture.json`의 최상위 필드는 `schema_version`, `run_id`, `lecture`, `segments`, `outline`, `summary_note`, `glossary`로 한다. `lecture`는 영상 ID·URL·제목·길이·자막 언어와 출처·생성 시각을 가진다. `segments`는 번호·시작 초·끝 초·정제된 문장이다. `outline`은 `chapters`와 그 안의 `children`으로 정확히 두 단계이며 각 항목은 문장 범위, 시간 범위, 제목, 요약을 가진다. `summary_note`는 `overview`와 `key_points`이고 핵심 내용 항목마다 참조 문장 번호를 가진다. `glossary` 항목은 용어·해설·처음 설명된 문장 번호와 시간을 가진다. 원본 자막은 로컬에 보존하고 공유 JSON에는 넣지 않는다.

공유 계약의 기계 검증은 필수 필드·타입, 단조 증가하는 시간, 영상 길이 안의 시간, 목차의 순서·중복 없는 전체 문장 범위, 모든 참조 문장의 존재를 확인한다. 의미 검토 단계는 요약과 용어가 실제 자막에서 뒷받침되는지 점검하고 불확실한 내용은 만들지 않는다. 기계 검증만으로 의미의 진실성을 증명한다고 간주하지 않는다. 스키마 변경 시 `schema_version`을 올리고 서버가 지원하지 않는 버전은 명시적 오류로 거부한다.

API 계약은 `POST /api/lectures`(인증된 JSON 업로드, `run_id` 기준 재시도 안전), `GET /api/lectures/{share_token}`(공유 페이지), `GET /api/lectures/{share_token}/data`(그 페이지의 JSON 조회)로 제한한다. 업로드 응답에는 `share_url`을 담는다. 수집과 콘텐츠 생성은 API에서 실행하지 않는다.

## 공유 페이지

페이지는 원본 YouTube 임베드 플레이어와 강의 제목·길이, 메인·세부 목차, 전체 요약노트, 용어집, 검색 가능한 정제 전사를 보여준다. 각 항목의 시간을 누르면 플레이어가 해당 시점으로 이동한다. 모바일 화면에서는 콘텐츠를 세로로 배치하고 목차를 접을 수 있게 한다. 임베드가 허용되지 않는 영상에는 같은 시점의 YouTube 링크를 제공한다. 별도의 영상 복사본, 사용자 계정, 공개 검색 페이지는 만들지 않는다.

## 오류와 복구

- URL 오류와 한국어 자막 부재: 수집 단계에서 영상 ID 또는 자막 상태를 알리고 종료한다.
- 중간 JSON 또는 최종 JSON 오류: 해당 단계에서 멈추고 검증 오류 위치를 출력한다. 유효한 이전 단계 산출물은 재사용한다.
- 업로드 통신 오류 또는 서버 거부: `lecture.json`을 보존하고 업로드 명령만 재실행하도록 안내한다.
- 업로드 재시도: 동일 `run_id`와 내용이면 기존 결과를 반환한다. 동일 `run_id`에 다른 내용이면 충돌 오류로 중단한다.
- 서버 저장 실패: 저장 성공으로 응답하지 않으며, 플러그인이 안전하게 재시도할 수 있게 한다.

## 검증과 배포

자막 파서·청크 경계·문장 번호·스키마·참조 무결성에 대한 단위 테스트와 업로드 인증·재시도·공유 URL·없는 토큰에 대한 API 테스트를 둔다. 실제 공개 한국어 강의 한 편으로 자막 확보부터 공유 페이지까지 확인하고, 3시간 분량의 자막 테스트 데이터로 분할과 조립을 검증한다. 사람이 목차·요약·용어집과 근거 시점의 정확성을 표본 검토한다.

Railway에는 웹/API 서비스와 PostgreSQL을 연결하고 `DATABASE_URL`, `LECTURE_UPLOAD_TOKEN`, `PUBLIC_BASE_URL`을 환경변수로 설정한다. 로컬에는 서버 URL과 업로드 토큰을 환경변수로 제공한다. 플러그인과 서버는 동일한 버전의 JSON 스키마를 사용한다. 첫 배포 후 인증되지 않은 업로드 거부, 정상 업로드, 공유 URL 조회, 시간 이동을 확인한다.

## 참고한 기존 동작과 외부 제약

로컬에 설치된 `lecture-pipeline` 0.11.1의 단계별 산출물과 시간 연결 방식을 참고했다. 이 설계의 코드와 웹/API 서버는 `D:\create-skills`에 새로 작성한다. 기존 플러그인의 `notes`는 주로 명령·링크 목록이므로 이번 설계의 전반 요약노트는 별도 필드로 정의했다.

YouTube 공식 자막 API의 조회·다운로드는 OAuth 권한이 필요하다. `youtube-transcript-api` 프로젝트는 클라우드 제공자 IP 차단 가능성을 문서화한다. Railway는 PostgreSQL 연결과 공개 HTTPS 도메인을 제공하며, YouTube IFrame API는 임베드 플레이어의 시점 이동을 지원한다.

- [자막 추출 라이브러리의 클라우드 IP 제약](https://github.com/jdepoix/youtube-transcript-api/blob/master/README.md?plain=1)
- [Railway PostgreSQL](https://docs.railway.com/databases/postgresql), [Railway 공개 네트워킹](https://docs.railway.com/networking/public-networking)
